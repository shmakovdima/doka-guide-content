# Статья «Статические генераторы сайтов» — дизайн

Источник задачи: GitHub issue doka-guide #5602 «Статические генераторы сайтов (Astro и др.)».
Автор материала (по issue): nasty23-star, но черновик готовим мы, по аналогии с существующей статьёй `tools/core-web-vitals/index.md`.

## Цель и аудитория

Максимально полная редакционная статья для Доки (жанр «статья», не «дока») — по объёму и глубине как Core Web Vitals. Целевой читатель — практикующий фронтенд-разработчик, выбирающий инструмент для реального проекта.

Формат — концептуальный обзор без сниппетов кода/конфигов, но каждый инструмент сопровождается ссылкой на официальную документацию и честным разбором плюсов и минусов (без маркетинга).

## Структура статьи

1. **Коротко** — что такое SSG и почему тема снова актуальна в 2026 году.
2. **Как работает статическая генерация** — рендеринг на этапе сборки (build time), результат — статические файлы. Кратко, без отдельной сравнительной таблицы, отличия от SSR/CSR/ISR (пара абзацев, не самостоятельный раздел).
3. **Зачем нужен SSG** — производительность (связка с Core Web Vitals: почти нулевой TTFB, быстрый LCP — ссылка на статью `tools/core-web-vitals`), безопасность (нет живого бэкенда — меньше поверхность атаки), простота и стоимость хостинга (статика на CDN), SEO.
4. **Когда SSG не подходит** — честные ограничения: время сборки на больших объёмах страниц, устаревание контента между сборками, отсутствие персонализации «из коробки», необходимость пайплайна пересборки/передеплоя. Отличия в поддержке инкрементальных сборок между инструментами (Gatsby Incremental Builds/DSG, Next.js ISR и т. д.) упоминаются здесь же.
5. **Islands Architecture (парциальная гидратация)** — отдельный раздел. Проблема «весь JS фреймворка гидрируется целиком», решение (гидрация только интерактивных «островов»), директивы Astro (`client:load`, `client:idle`, `client:visible`, `client:media`, `client:only`), связь с INP (отсылка к CWV-статье). Упоминание альтернативных подходов (Qwik — резюмируемость, technically не islands, но постоянно сравнивается).
6. **Обзор генераторов** — группировка по экосистеме/языку для навигации:
   - **React-экосистема**: Next.js (SSG-режим), Gatsby, Docusaurus
   - **Vue-экосистема**: Nuxt (static-режим), VitePress, VuePress
   - **Islands / резюмируемость**: Astro, Fresh, Qwik City, Marko, Enhance
   - **Без UI-фреймворка / компилятор-центричные**: Hugo, Zola, Jekyll, Eleventy, Hexo, Pelican
   - **Отдельно**: SvelteKit (static adapter)

   Для каждого инструмента — единый формат: что это и на чём написан, шаблонизатор, ключевая особенность, поддержка islands/партиальной гидратации (да/нет/аналог), для чего лучше всего подходит, честные плюсы и минусы, статус проекта на 2026 год, ссылка на официальную документацию.

   Статусные темы освещаются прямо и без оценочных суждений:
   - Gatsby — фактический режим обслуживания после интеграции с Netlify, нет значимых новых фич, не рекомендуется для новых проектов (со ссылкой на источник).
   - Eleventy — ребрендинг в «Build Awesome» с платным тиром, приостановленный Kickstarter, смешанная реакция сообщества; OSS-ядро остаётся бесплатным и обратно совместимым (со ссылкой на источники).
   - VitePress — на GitHub числится alpha-тег следующей мажорной версии; при финальной проверке фактов перед публикацией сверить с npm dist-tag `latest`, чтобы не писать голословно «VitePress в альфе».
   - Qwik City — 2.x всё ещё в бете, статус отражается как есть.

7. **Как выбрать генератор** — практический чек-лист критериев: стек и язык команды, тип контента (блог/документация/маркетинг/e-commerce), масштаб сборки (число страниц), зрелость экосистемы плагинов/тем, потребность в интерактивности, воркфлоу редактирования контента для нетехнических авторов, модель стоимости хостинга.
8. **Итоги / шпаргалка** — сводная таблица по всем инструментам (язык, шаблонизатор, islands/гидрация, для чего лучше всего) — аналог таблицы порогов в CWV-статье.
9. **На практике** — обязательный по styleguide Доки раздел с личным опытом/советами автора.
10. **Источники** — ссылки на все использованные материалы: официальная документация каждого инструмента, GitHub-репозитории (как источник версий/статусов), State of JS 2025 (опрос по мета-фреймворкам), Jamstack.org, обсуждения статуса Gatsby и ребрендинга Eleventy, patterns.dev (islands architecture reference).

## Правила при написании

- Каждый спорный или версионно-чувствительный факт (статус проекта, номер версии, бенчмарк) в тексте сопровождается инлайн-ссылкой на источник — так, как принято оформлять ссылки в Доке (содержательный анкор, не «здесь»/«тут»).
- Оформление и тон — по `docs/superpowers/specs` (см. [[reference_styleguide]] в памяти сессии): маркдаун-first, `##`–`####` заголовки, ёлочки-кавычки, без канцелярита, на «вы», обязательная буква Ё.
- Не публиковать голословные маркетинговые цифры (например, проценты сокращения JS-бандла из блогов) без пометки «по оценке [источник]» — исследование показало, что многие такие цифры не подтверждены официальной документацией инструментов.
- Иллюстрации/диаграммы в этой сессии не проектировались — при необходимости обсуждаются отдельно перед написанием черновика с картинками.

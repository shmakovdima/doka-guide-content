# WebMCP Browser Benchmark Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build an isolated synthetic ecommerce benchmark that can compare visual browser control, Playwright MCP, and WebMCP using identical tasks, state, and model settings.

**Architecture:** A small Node HTTP server owns deterministic catalog, cart, checkout, and reset state. A vanilla browser client renders the store and registers WebMCP tools backed by the same HTTP operations. A runner layer defines mode adapters, validates backend state through an oracle, and writes reproducible JSONL metrics. Model execution is configured but never required by local tests.

**Tech Stack:** Node.js 22+, vanilla HTML/CSS/JavaScript, Node built-in test runner, Playwright, JSON fixtures, no frontend framework, no database, no real payment provider.

## Global Constraints

- Keep all implementation under `webmcp-browser-benchmark/`.
- Do not modify `doka-demo/platform`, `webmcp-shared-state-demo/`, or existing article files.
- Use exactly 24 deterministic products across headphones, keyboards, mice, and monitors.
- Use integer cents for all prices and a fixed USD 5.00 shipping fee.
- Reset state before every run; the first reset order ID is `order-0001`.
- Do not make model calls in unit tests, browser tests, smoke setup, or application startup.
- Do not expose hidden benchmark answers through WebMCP schemas or results.
- Do not use real payment, credentials, analytics, or customer data.
- Use ordinary hyphen-minus characters only.

# План статьи о WebMCP для HackerNoon

Фокус: преимущества WebMCP. Бенчмарк - доказательство, а не тема статьи.
Голос: первое лицо, "я". Сначала русский текст, после утверждения - английский.
Объем 1800-2200 слов, один пример кода, компактные таблицы. Без раздела с оговорками.
Ранее опубликованных статей о WebMCP у автора нет, поэтому WebMCP объясняется полностью.

1. Лид (100-150 слов). Агент покупает наушники: ищет фильтр, путает цены, после каждого клика перечитывает страницу. Сколько стоит эта работа и что остается, если сайт сам описывает свои действия. Главная цифра сразу: от 52% до 97% меньше токенов.

2. Как агенты работают с сайтами сейчас (200 слов). Скриншоты и computer use, DOM и селекторы, accessibility tree через Playwright MCP. Во всех трех агент восстанавливает смысл интерфейса, который сайт уже знает. Обычный MCP-сервер: найти, установить, подключить для каждого сервиса, и он не видит состояние открытой вкладки.

3. Что такое WebMCP (350-400 слов). Браузерный API, `document.modelContext.registerTool()`: имя, описание, JSON Schema аргументов, `execute`. Инструмент работает внутри открытой вкладки: та же сессия, то же состояние, тот же UI. Человек кликает, агент вызывает функции, оба меняют одно приложение. Пользователю ничего не нужно устанавливать. Аннотации `readOnlyHint` и `consequentialHint`. Статус: экспериментальный API в Chrome, одной фразой. Пример кода: `set_cart_item`.

4. Преимущества WebMCP (300 слов). Меньше токенов и шагов, общий UI и состояние с человеком, ничего не нужно ставить, логика сайта переиспользуется, сайт сам решает, какие действия открыть агенту.

5. Как я это проверил (300 слов). Northstar Store, задачи T1-T5, три интерфейса к одному магазину, два оракула, пять инструментов WebMCP.

6. Результаты (400-500 слов). Сводная таблица по четырем прогонам, абзац на каждый: Nemotron 3 Ultra, Codex, Claude Opus 5.5, скриптовый прогон. Способ подсчета токенов в каждом. Пример T5 у Nemotron: 14 тыс. против 318 тыс. и 530 тыс. Порядок WebMCP < Playwright MCP < DOM везде.

7. Почему разрыв такой большой (250 слов). Accessibility tree описывает виджеты, WebMCP описывает операции. Каждый лишний шаг - перечитывание растущей страницы.

8. Что делать тем, кто делает сайты (250 слов). Несколько инструментов на бизнес-шаги. Серверная проверка обязательна, аннотации ее не заменяют. WebMCP там, где важно состояние вкладки, обычный MCP для фоновых возможностей.

9. Финал и ссылки (100 слов). Демо, репозиторий, матрицы, приглашение прогнать со своей моделью.
